# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added
- Configurable request deadline for the SSE streaming path (`/api/generate`, `scheduler_settings.streaming_request_timeout_seconds`, default 60s). An expired request is finished with partial output if any tokens were generated, otherwise failed with an SSE `error` event.
- Streaming-path metrics (queue latency, per-step batch size, per-step token throughput) via a new `streaming_metrics` singleton, exposed through `GET /api/metrics`.
- Additional continuous-scheduler-only metrics on `streaming_metrics`/`GET /api/metrics`: `average_batch_occupancy` (active requests as a fraction of `max_batch_size`, sampled every step), `average_cache_utilization` (used paged-KV blocks as a fraction of pool capacity, sampled every step the paged cache has already been built), and two counters, `timeout_evictions` and `cancelled_evictions`, incremented wherever `ContinuousScheduler` already drops a request for missing its deadline (`_add_new_requests()`, `_evict_expired_requests()`) or for a disconnected client (`_evict_cancelled_requests()`).
- Cancellation check in `ContinuousScheduler._step()` so disconnected SSE clients stop consuming compute mid-generation, mirroring the equivalent check already present on the batch path.
- Client-supplied `idempotency_key` on `/api/generate` (`scheduler/idempotency.py`, `IdempotencyStore`) to deduplicate retried requests: a repeated call with the same key replays a completed result, returns `409` if the original is still in-flight, or retries fresh if the original failed.
- Server-side single-retry on transient generation failure for the streaming path (`ContinuousScheduler._step()`); a second failure fails every active request with an SSE `error` event.
- `scheduler_config` section in `settings/config.yaml` (`SchedulerSetting`) centralizing streaming/batch timeout defaults and the idempotency-key TTL.
- `stop` field on `GenerateRequest` (`schemas/schemas.py`, up to 4 non-empty strings): generation halts before emitting a matching stop sequence. Checked against the full decoded text on both the streaming path (`ContinuousScheduler._dispatch_tokens`) and the non-streaming batch path (`InferenceEngine.generate_batch`), and independently re-checked in `streaming/stream_manager.py` so the stop text itself is never flushed to an SSE client even if it spans the last few tokens already in flight. Shared matching logic lives in `utils/stop_sequences.find_stop_index()`. The CLI's `start` REPL sets default stop sequences (`\nuser:`, `\nUser:`) to guard against models that don't reliably emit EOS at the turn boundary and keep generating a hallucinated next turn.
- `ephemeris-serve serve` CLI command (`cli/main.py`): starts the inference server itself (equivalent to `python main.py`) with `--model`, `--host`, `--port`, `--workers`, and `--reload` options, so a model can be picked without editing `settings/config.yaml`. `--model` is threaded through via a new `EPHEMERIS_MODEL_NAME` env var read by `ModelSetting` (`settings/settings.py`) rather than an in-process mutation, so it's inherited correctly even when `--workers > 1` makes uvicorn spawn fresh worker processes.
- Runtime model hot-swapping, without a process restart: `GET /api/model` / `POST /api/model` (`api/routes.py`, `schemas.ModelSwapRequest`/`ModelSwapResponse`) backed by a new `scheduler/model_swap.py` coordinator that drains in-flight requests (`ContinuousScheduler.active_requests`, `request_queue`, `batch_request_queue`) before swapping, then replaces the model/tokenizer via new `ModelLoader.reload()` / `TokenizerService.reload()` methods and invalidates the caches that were sized for the old model's architecture (`InferenceEngine.invalidate_model_cache()`, `ContinuousScheduler.invalidate_paged_cache()`). `/generate` and `/generate_batch` reject with `503` for the duration of a swap. If the new model or tokenizer fails to load, the previously-loaded one is left running untouched (tokenizer is explicitly rolled back if the model half of the swap fails, so the two can never end up mismatched). Exposed in the CLI REPL as `/model [name]`. New `scheduler_config.model_swap_drain_timeout_seconds` setting (default 30s).
- CLI visual redesign (`cli/main.py`): the assistant's reply now streams inside a live, word-wrapped bordered box (`_StreamingBox`) instead of plain inline text; a boxed connection-status panel (`_print_welcome`) replaces the old single-line banner; a startup splash (`_print_splash`) shows a block-character rendering of the Ephemeris Serve logo (`cli/logo.py`, precomputed from `asset/images/ephemeris-serve-logo.svg`'s vector geometry) with a "press Enter to continue" gate, and is skipped gracefully on terminals too narrow to fit it.
- README.md, TECHNICAL_DOCUMENTATION.md, and CHANGELOG.md now all show the Ephemeris Serve logo (`asset/images/ephemeris-serve-logo.svg`) at the top, consistent with the CLI splash.
- Friendly `--creativity` preset on `ephemeris-serve start` (`deterministic`, `balanced`, `creative`, `high-freedom`, mapping to temperatures 0.0/0.7/1.0/1.5) as an alternative to a raw `--temperature` float; `--temperature` still wins if both are given. Also changeable mid-session with a new `/creativity [preset|number]` REPL command (accepts either a preset name or an exact number), taking effect from the next turn onward -- purely client-side, no server round-trip, unlike `/model`. The resolved setting is shown in the REPL's connection-status panel (e.g. `Creativity: balanced (temperature 0.7)`).
- Arrow-key line editing and persistent command history in the `ephemeris-serve start` REPL (`cli/main.py`): importing the standard-library `readline` module gives `click.prompt`'s underlying `input()` proper left/right cursor movement and up/down history recall, which previously just inserted raw escape sequences into the prompt. History is loaded from and saved to `~/.ephemeris_serve_history` (capped at 1000 entries via `readline.set_history_length()`) so it persists across sessions, like a shell. `readline` isn't available on Windows without a third-party `pyreadline3` install, so the import is wrapped in a `try`/`except ImportError` and the REPL falls back to plain `input()` behavior there.

### Fixed
- **Retry granularity on the streaming path**: `ContinuousScheduler._step()`'s single retry-on-failure previously operated at whole-step granularity -- a batched forward pass fails or succeeds as a unit, so one poisoned request (bad cached state, a degenerate shape, ...) failed every co-batched request along with it. After two whole-batch failures in a row, the scheduler now retries each currently-active request in its own batch of one via a new `ContinuousScheduler._retry_requests_individually()` (built on new `_build_batch_inputs()`, factored out of `_prepare_batch()`, and a `_forward_and_sample()`/`_dispatch_tokens()` now parameterized on an explicit request list instead of always `self.active_requests`): a request that succeeds alone is dispatched normally, and only a request that still fails in isolation is failed, via a new `_fail_single_request()` (replacing `_fail_active_batch()`, which unconditionally failed every active request).
- **Root cause of the `MPS backend out of memory` crashes**: `InferenceEngine.forward_step()` -- the continuous scheduler's only forward-pass entry point, used by every `/api/generate` call -- never wrapped its model call in `torch.no_grad()` (unlike `generate()`/`generate_batch()`, which already did). Every step built a full autograd graph across all transformer layers that nothing ever released, since nothing calls `.backward()` on it -- a steady per-step leak of genuinely-referenced (not cached) memory that `empty_cache()` could never reclaim, which is why the proactive/reactive cache-clearing added earlier didn't stop the crashes. Confirmed via a live-memory diagnostic against the real model: MPS memory grew by a fixed amount (~25-30MB) on every single request before this fix, and was perfectly flat across 20+ requests (including full multi-token decode loops) after it.
- `BatchScheduler` no longer double-records queue latency per batch request (`_collect_batch()` and `process_batch()` both called `metrics.record_queue_latency()` for the same request; now recorded once, in `_collect_batch()`).
- `BatchScheduler.request_timeout` is now wired to the deadline enforced in `api/routes.py`'s `POST /generate_batch`, replacing two independently hardcoded `20.0` literals that happened to match.
- `InferenceEngine.generate_batch()` no longer leaves `InferenceRequest.generated_tokens` unpopulated -- tokens were previously appended to a wrapper object's copy that was never synced back, so `average_token_throughput_per_sec` always reported `~0` for the batch path in both `GET /api/metrics` and every `/generate_batch` response.
- CLI SSE delta parsing (`cli/main.py::_stream_reply`) stripped *all* leading/trailing whitespace off every `data:` frame instead of just the single mandatory separator space after `data:` -- since streamed deltas often start with their own meaningful leading space (a word boundary), this silently ran consecutive words together in the REPL's rendered output (e.g. `toprovide examplesof`). Now only one leading space is stripped, per the SSE spec.
- CLI REPL fed a mid-stream `[server error]`/`[connection error]` message directly into the still-open `_StreamingBox`, running it straight into the last partial line of generated text with no visual separation -- making a server-side failure look like part of the model's own reply. The box is now always closed on whatever content actually streamed, and the error is printed as its own red line below it.
- `ContinuousScheduler._step()`'s single retry-on-failure didn't actually help against an OOM-shaped failure, since it retried against the exact same (still-exhausted) device memory state that just failed. It now calls a new shared `utils/device_cache.empty_device_cache()` before retrying, and again once the scheduler has no active requests left. `BatchScheduler` now clears once per processed batch, and `scheduler/model_swap.py` now clears again *after* `ContinuousScheduler.invalidate_paged_cache()` drops the old paged cache's last reference (previously the only cache-clear during a swap ran inside `ModelLoader.reload()`, before that reference was dropped, so the old cache's memory was never actually reclaimed). `ModelLoader.reload()` now calls the same shared helper (previously had its own private copy).
- Device memory is now released *proactively*, before it ever reaches the device's ceiling, instead of only reactively (on retry/idle). New `utils/device_cache.device_memory_pressure()`/`maybe_empty_device_cache()` read `torch.mps.driver_allocated_memory()`/`recommended_max_memory()` (CUDA: `memory_reserved()`/device total) every scheduler step -- a cheap metadata query, not a device sync -- and clear once usage crosses 70% of budget. This closes the gap where a single long-running request that never hit a failure or an idle gap could accumulate cached-but-unused memory all the way to `MPS backend out of memory`.
- `ContinuousScheduler._forward_and_sample()` applied repetition penalty against `batch_inputs.input_ids` -- this step's new-tokens-only slice (a single token during decode) -- instead of each request's full generated history. `torch.unique()` on one token has nothing to penalize, so the configured `repetition_penalty` was silently a no-op after the first decode step, letting the model repeat/ramble without the penalty ever pushing back (observably: responses that just kept generating instead of naturally reaching EOS). It now passes each active request's full `input_ids` (prompt + everything generated so far); `InferenceEngine.apply_repetition_penalty()` now accepts either a dense same-length-per-row tensor or a ragged list of per-row tensors, since requests in a mixed prefill/decode batch don't share one history length.
- `asset/images/ephemeris-serve-logo.svg` was invisible on dark backgrounds (e.g. GitHub's dark theme) -- every shape's stroke/fill was hardcoded to a fixed near-black (`rgb(11,11,11)`) via inline `style` attributes, which take precedence over the `var(--text-primary)` presentation attributes the SVG otherwise (unusably, standalone) declares. Added a `<style>` block with `@media (prefers-color-scheme: dark)` overrides (`!important`, scoped to the SVG's root `id`) so the mark renders near-black in light mode and near-white in dark mode; works standalone (e.g. loaded via `<img src>` in a README) since `prefers-color-scheme` is a system-level media feature, unlike inherited CSS custom properties.
- Client-facing error messages could leak raw internal exception text -- e.g. an OOM's PyTorch-internal message (memory sizes, env var hints) reached the CLI verbatim via the SSE `error` event (`ContinuousScheduler._fail_active_batch`) and via `/generate_batch`'s and `POST /api/model`'s `500` responses (`detail=str(exc)`). All three now send a generic `utils/errors.INTERNAL_ERROR_MESSAGE` ("Internal server error") instead; the real exception is still logged in full server-side and still set on the request's `future` for internal bookkeeping, just never put on the wire. Deliberately-authored, already-safe messages (e.g. `409`/`503`/`504` conflict/timeout details) are unaffected. The CLI now renders every server-reported failure as `[server error <code>] <message>`, reading `detail` out of the JSON error body rather than dumping the raw response text.

### Changed
- README/Makefile now show `ephemeris-serve start`/`ephemeris-serve serve` directly instead of `uv run ephemeris-serve start` -- both work as plain commands once the project's virtualenv is active, and the README's CLI section now documents `ephemeris-serve serve` (previously undocumented there, despite already existing).
- CLI startup splash logo (`cli/logo.py`) is now smaller and bolder (36-wide block art with a thicker stroke threshold, down from 48-wide) so it fits more terminals without wrapping.
- `GET /api/metrics` now reports `{"batch": ..., "streaming": ...}` instead of a single merged snapshot.
- `InferenceEngine.generate_batch()` no longer imports `ActiveRequest` from `scheduler.request`; it depends on a local `GenerationRequest` `typing.Protocol` instead. `ActiveRequest` has been removed.
- Extracted `/generate_batch`'s response-metrics assembly into `metrics.summarize_batch_response_metrics()`, and both `/generate`'s and `/generate_batch`'s disconnect-cancellation polling into a shared `api.routes.cancel_futures_on_disconnect()` -- removing duplicated inline closures and their TODO comments.
- Bumped minimum/CI-tested Python version to 3.12 (dropped 3.11 from the CI matrix).
- `resolve_device()`'s `"auto"` device-detection priority (`settings/settings.py`) now checks CUDA before MPS (previously MPS was checked first before CUDA), so a machine with both an NVIDIA GPU and MPS available prefers CUDA.
- README's CLI chat client section now includes three screenshots (`asset/images/chat-cli1.png`/`chat-cli2.png`/`chat-cli3.png`) of the REPL in action: the startup splash, the `/model` command, and a live chat session.
