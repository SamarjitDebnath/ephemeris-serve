API Reference

Base URL: http://<host>:8000 direct, or http://<host>:8080 through the bundled nginx reverse proxy. Routes under /api are mounted from api/routes.py; / and /health are top-level.

Authentication

Every /api route takes an API key as Authorization: Bearer <key>, in two tiers. / and /health never require one.

TierServer environment variableCovers
OrdinaryEPHEMERIS_SERVER_API_KEYS/api/generate, /api/generate_batch, GET /api/model, /api/metrics
AdminEPHEMERIS_SERVER_ADMIN_API_KEYSadditionally POST /api/model

Both hold a comma-separated list, so keys rotate by adding the new one before removing the old. POST /api/model is gated separately because it makes the server download and load an arbitrary Hugging Face repo. A missing or unrecognized key returns 401; an ordinary key on the admin route returns 403.

With no keys configured every route is open — the local-development default. Any server reachable from outside localhost must set at least the ordinary tier.

Rate limiting

/api/generate and /api/generate_batch are throttled per API key — per client address when authentication is disabled — by a token bucket for request rate plus a separate cap on concurrent generations. Configured under rate_limit_config in settings/config.yaml and off by default, like authentication.

A batch is charged its sub-request count, not 1, so batching cannot be used to bypass the limit. Exceeding either limit returns 429 with a Retry-After header giving the seconds until the bucket refills.

The buckets live in each worker process, so a server started with --workers 4 enforces four times the configured numbers. That is adequate for abuse prevention, not for billing-grade quota. The limit_req in the bundled nginx config is a complementary outer layer: it keys on client address and cannot see batch size, so neither replaces the other.

curl -H "Authorization: Bearer $EPHEMERIS_CLIENT_API_KEY" \
  http://localhost:8000/api/metrics

POST /api/generate

Enqueues an InferenceRequest and returns a streaming text/event-stream response of decoded tokens. Returns 503 while a model swap is in progress, or 429 when rate limiting is enabled and the caller is over budget.

Request body

FieldTypeDescription
promptstring (required)The input text for the model. Must be non-empty.
max_tokensinteger1–2048. Optional.
temperaturefloat0.0–2.0. Optional.
top_kintegerKeep only the k highest-probability tokens. 0 disables top-k filtering. Optional; falls back to model_config.top_k.
top_pfloatNucleus sampling mass, greater than 0 and at most 1.0. 1.0 disables top-p filtering. Optional; falls back to model_config.top_p.
idempotency_keystringOptional client-supplied key (max 200 chars) to deduplicate retried requests. A repeated key replays the cached result while the original is still in flight, or returns 409 if it's genuinely a duplicate in-flight request.
stopstring[]Up to 4 non-empty stop sequences; generation halts before emitting any of them.

Example

curl -N -H "Accept: text/event-stream" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $EPHEMERIS_CLIENT_API_KEY" \
  -X POST \
  -d '{"prompt":"Hello world","max_tokens":50,"temperature":0.7,"top_k":40,"top_p":0.9}' \
  http://localhost:8000/api/generate

POST /api/generate_batch

Non-streaming batched generation. Accepts one or more requests and returns aggregated text output once every item in the batch has completed. Returns 503 during a model swap, 504 on batch timeout, 499 if the client disconnects mid-batch, and 429 when rate limiting is enabled and the batch exceeds the caller's remaining budget.

Request body

FieldTypeDescription
requestsGenerateRequest[] (required)At least one generation request, same shape as /api/generate's body.

Response body

FieldTypeDescription
outputsstring[]Decoded output text for each item in the batch, in order.
batch_sizeintegerNumber of requests processed in the batch.
queue_latency_msfloat | nullAverage queue latency for this batch.
token_throughput_per_secfloat | nullToken throughput for this batch.

Example

curl -H "Content-Type: application/json" \
  -H "Authorization: Bearer $EPHEMERIS_CLIENT_API_KEY" \
  -X POST \
  -d '{"requests": [{"prompt": "Hello world", "max_tokens": 50, "temperature": 0.7}]}' \
  http://localhost:8000/api/generate_batch

GET /api/model

Returns the model this worker currently has loaded, plus how far a swap has spread across the worker pool.

FieldTypeDescription
model_namestringHugging Face model repo id currently loaded by the worker that answered.
generationinteger | nullMonotone counter for the published model target. null when cross-worker coordination is disabled.
converged_workersinteger | nullWorkers that have reached this generation.
known_workersinteger | nullWorkers that have reported any generation. Poll until this equals converged_workers.

POST /api/model

Hot-swaps the model this server is running without a process restart. In-flight requests are drained before the swap; /api/generate and /api/generate_batch reject with 503 for the duration. Returns 409 if a swap is already in progress, 504 if draining exceeds the timeout.

With multiple workers a swap is not atomic, and the API says so rather than hiding it: each worker drains its own in-flight requests before reloading, and those drains finish at different times. Set scheduler_config.model_state_dir to a path shared by every worker and the handling worker publishes a new generation that the others converge on; the response then carries generation, converged_workers and known_workers, and a client polls GET /api/model until the two counts match. Leave the setting empty and only the worker handling the request reloads.

Request body

FieldTypeDescription
model_namestring (required)Hugging Face model repo id to load.
drain_timeout_secondsfloatMax seconds to wait for in-flight requests to finish before swapping. Defaults to scheduler_config.model_swap_drain_timeout_seconds.

Example

curl -H "Content-Type: application/json" \
  -H "Authorization: Bearer $EPHEMERIS_CLIENT_API_KEY" \
  -X POST \
  -d '{"model_name": "Qwen/Qwen2.5-0.5B"}' \
  http://localhost:8000/api/model

GET /metrics

Prometheus exposition format: raw counters, gauges and histograms rather than the rolling averages above. Requires the optional metrics extra (pip install -e ".[metrics]") and metrics_config.prometheus_enabled; when disabled the route is not registered at all, so a scraper sees a clean 404 rather than an endpoint reporting itself unavailable.

This is deliberately not derived from /api/metrics. That endpoint averages over the last 1000 samples — a window whose duration varies with traffic — which is precisely what a time-series backend must not be handed pre-aggregated.

MetricTypeDescription
ephemeris_queue_latency_secondshistogramTime between enqueue and admission.
ephemeris_token_throughput_per_secondhistogramTokens per second per scheduler step.
ephemeris_batch_sizegaugeRequests in the most recent batch.
ephemeris_batch_occupancy_ratiogaugeActive requests as a fraction of max_batch_size.
ephemeris_kv_cache_utilization_ratiogaugeUsed KV blocks as a fraction of pool capacity.
ephemeris_timeout_evictions_totalcounterRequests dropped at their deadline.
ephemeris_cancelled_evictions_totalcounterClients that disconnected mid-generation.
ephemeris_kv_blocks_reclaimed_totalcounterKV blocks returned to the allocator by an idle trim.

All are labelled path="batch" or path="streaming", matching the two top-level keys in the JSON endpoint. Authentication follows metrics_config.require_auth; see deploy/prometheus/README.md for scrape configuration and the per-gauge multiprocess modes.

Example

curl -H "Authorization: Bearer $EPHEMERIS_CLIENT_API_KEY" \
  http://localhost:8000/metrics
