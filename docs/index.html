EPHEMERIS · SERVE
Self-hosted · Open source · Single process

Never wait for a full batch.

Ephemeris Serve is an LLM inference server built around one idea: a request should never sit idle while the batch fills up. A continuous scheduler folds new requests into the batch mid-flight, a paged KV cache lets prefill and decode share the same forward pass, and every token streams back over SSE the moment it's sampled.

What the scheduler actually does

ten things, working together

01

Continuous scheduling

New requests join an already-running batch step, instead of waiting for the current one to finish.

02

Mixed prefill + decode

A paged KV cache lets a brand-new prompt and an in-progress generation share the same forward pass. Its block pool gives capacity back when traffic dies down, so one burst doesn’t set the memory floor for the process lifetime.

03

SSE token streaming

Decoded text streams to the client the moment each token is sampled — no buffering full sentences.

04

Cancellation & timeouts

A disconnected client stops consuming compute mid-generation; deadlines evict requests that overstay.

05

Hot model swap

Swap the loaded model via /api/model, draining in-flight requests first — no restart. Across a worker pool the swap propagates and the API reports how far it has converged, rather than pretending it was atomic.

06

Metrics & health

Queue latency, batch occupancy, and cache utilization on /api/metrics, plus raw Prometheus counters and histograms on /metrics — the second is not the first pre-averaged.

07

Short-request fairness

A burst of long generations can’t starve short ones: the scheduler reserves batch slots for them and ages waiting requests forward, so neither lane starves the other.

08

Per-key rate limiting

A token bucket and a concurrency cap, keyed by API key rather than address. A batch is charged its sub-request count, so batching can’t be used to slip past the limit.

09

API-key auth

Two tiers of bearer key: an ordinary tier for generation and read-only routes, and a separate admin tier for the one route that loads an arbitrary model. Constant-time comparison, keys never logged.

10

Production deployment

An nginx reverse proxy config (TLS, rate limits, SSE-safe buffering) and a systemd unit ship in deploy/, with a walkthrough covering keys, supervision, and pointing clients at the result.

Quick start

python 3.12+ · gpu optional

Prerequisites: Python 3.12+, a supported GPU (optional), and access to the Hugging Face Hub for authenticated model downloads.

One command
# sync deps, install the CLI, start the server
$ make build-ephemeris
Plain venv
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -e .
$ python main.py
Chat with it
# anywhere — no torch needed
$ pip install ephemeris-cli
$ ephemeris start
Pick a model
$ ephemeris-serve serve \
    --model Qwen/Qwen2.5-0.5B

CLI chat client

ephemeris start

The client ships as its own distribution, ephemeris-cli, depending only on click, httpx and pyyaml — install it on a laptop to talk to a remote server without pulling torch or transformers. ephemeris start is a REPL over /api/generate's SSE stream; the server itself is started by the separate ephemeris-serve command. --creativity picks a friendly sampling-temperature preset (deterministic, balanced, creative, high-freedom); both the model and the creativity level can be changed mid-session with /model and /creativity.

Metrics you can actually scrape

GET /metrics

Enable the optional metrics extra and the server exposes raw Prometheus counters, gauges and histograms alongside the rolling-average JSON on /api/metrics. The two are not the same numbers in different clothes: the JSON averages over the last 1000 samples, a window whose duration moves with traffic, which is exactly what a time-series database must not be handed pre-aggregated. Below, ephemeris_batch_occupancy_ratio scraped every two seconds through a burst-and-idle load — each spike is the batch filling to max_batch_size, each trough the scheduler draining before the next burst arrives.
